FITS/XISF development checklist

Recorded: 2026-10-31. Status: in progress; unchecked items are not implemented promises. Work through the steps in order unless a dependency or a newly discovered defect requires a change. Keep the stable task IDs when splitting work into issues or PRs. Check a task only after its completion criteria and relevant tests pass.

Starting point

  • Ordinary multi-HDU FITS images, ASCII/binary table reading, scaling, image nulls, checksums, long strings and HIERARCH are already supported.
  • XISF already supports monolithic/distributed containers, zlib/LZ4/LZ4HC/Zstandard, shuffling/subblocks, checksums, unsigned/real/complex pixels, rich properties, tables, ancillary metadata, signatures, and native astrometric solutions.
  • The restricted FITS WCS helper is separate from the native XISF evaluator, which already supports seven projections and distortion models. Unsupported coordinate evaluation does not necessarily prevent loading pixels or preserving headers.
  • The local example corpus contains eleven FITS files and 73 XISF files (79 images).
  • This list comes from code inspection and the code review. It is not an exhaustive standards-conformance certification.

Phase 1 — Define and independently verify the support contract

  • [x] AV-001 — Publish a feature-support matrix. Track read, write, edit, preserve, and evaluate separately for each format feature. Distinguish native format requirements, optional conventions, and image-processing features. Done when: the matrix describes the current APIs accurately, links to tests, and explicitly identifies unsupported behaviour without claiming full conformance.

  • [ ] AV-002 — Expand independent interoperability fixtures. Add redistributable FITS reference fixtures and independently produced XISF examples covering codecs, sample types, layouts, containers, tables, and real astrometric solutions. Keep large/private photographs local and record provenance and hashes. Done when: tests compare independently known pixels/metadata, and files written here are checked with independent readers. Reference tools are development tools, not required runtime dependencies.

  • [x] AV-003 — Close the optional external-resource timeout gap. Make HTTP body reads observe cancellation/timeouts; document cooperation required from custom resolver streams. Preserve default-disabled network access. Done when: a local test server stalling after headers is cancelled, caller ownership remains correct, and no real external service is needed by tests.

Phase 1 evidence (2026-11-01): support matrix completes AV-001; XISF network tests complete AV-003. AV-002 is partial: 60 committed independent fixtures, 46 reverse-reader checks, and independent hashes for all 79 images in the 73-file local XISF corpus are implemented. The following substeps retain the original completion criteria:

  • [x] AV-002.1: Redistributable FITS images, tables and independent TAN reference coordinates.
  • [x] AV-002.2: Independent XISF codec/type/mono/RGB and attached/embedded fixtures, with exact pixels, provenance, hashes and licenses; independent checks of writer output.
  • [x] AV-002.3: Local real photographs, multiple images, legacy astrometry metadata preservation and incomplete-thumbnail negative cases, with repeatable tests.
  • [ ] AV-002.4: Independent distributed XISF containers, XISF tables, UInt64/complex pixels and big-endian/interleaved storage, with known reference values and reverse-reader checks.
  • [ ] AV-002.5: A real native Revision 1 AstrometricSolution:* solution, including distortion and independent coordinate reference values. The downloaded legacy PCL:AstrometricSolution:* files cannot validate this evaluator.

See interoperability for provenance, exact coverage and required follow-up.

Phase 2 — Build a consistent scientific image-access foundation

  • [ ] AV-004 — Design shared typed image and pixel-access contracts. Support explicit axes, channels, layout, sample types, scaling and missing-value masks. Keep native FITS/XISF documents accessible so a common view does not discard metadata. Preserve existing APIs or provide a documented migration path. Done when: the same operation can consume either format without first converting the entire file or forcing all samples through double.

  • [ ] AV-005 — Add exact typed FITS pixel reads. Expose stored and physical values explicitly, including unsigned offset conventions and integer boundaries. Define behaviour when arbitrary scaling cannot be represented exactly. Done when: UInt64 values above 2^53, signed integers, BLANK, floating-point special values and overflow policies have independent regression tests. Depends on: AV-004.

  • [ ] AV-006 — Add metadata-only opening and source indexing. Inspect headers, HDUs/images, geometry and block locations without materializing every payload. Define source lifetime, ownership and behaviour if source files change. Done when: a large-file header scan uses bounded memory and selected content can be opened without loading unrelated HDUs/images.

  • [ ] AV-007 — Add format detection and a convenient opening API. Detect content rather than relying solely on filename extensions. Offer native-document access alongside shared image access, with clear unsupported/corrupt-input diagnostics. Done when: FITS, monolithic/distributed XISF headers and supported transport wrappers are identified consistently, including misleading filenames. Depends on: AV-004, AV-006; extend detection as compression is implemented.

Phase 3 — Support common compressed FITS images

  • [ ] AV-008 — Integrate gzip-wrapped FITS (.fits.gz). Add automatic reading and explicit writing options; retain caller-stream ownership and resource limits. Done when: path/stream APIs handle independently compressed files, truncated input and decompression limits. Document sequential-access costs.

  • [ ] AV-009 — Recognize tiled compressed-image HDUs. Interpret ZIMAGE, ZBITPIX, ZNAXIS, ZTILE and codec metadata instead of exposing compressed images only as generic tables. Preserve access to the original storage representation. Done when: compressed images appear in image discovery with correct geometry, and unsupported codecs are reported precisely. Depends on: AV-006.

  • [ ] AV-010 — Implement Rice and GZIP tile decoding/encoding. Cover applicable GZIP variants, edge tiles, integer storage, floating-point quantization/dithering, and undefined-pixel handling. Separate lossless storage from explicitly lossy modes. Done when: independent compressed fixtures decode correctly and reference readers accept output; quantized modes have explicit accuracy contracts. Depends on: AV-009.

  • [ ] AV-011 — Add HCOMPRESS and PLIO support. Implement supported lossless modes first and require explicit options for lossy modes. Done when: independent fixtures, malformed tiles and algorithm-specific parameter boundaries are covered, with documented supported modes. Depends on: AV-009, AV-010.

Phase 4 — Make large-image work bounded and cancellable

  • [ ] AV-012 — Add row, region, channel and cube-plane reads. Provide exact typed reads and caller-provided buffers through the shared access contract. Read uncompressed regions directly and use tile/subblock access where possible. Done when: small requests avoid unrelated payloads when storage permits; whole-codec-block decoding requirements are explicit rather than hidden. Depends on: AV-004–AV-006, AV-009 for tiled FITS.

  • [ ] AV-013 — Add streaming writes and compression. Avoid retaining every raw/compressed attachment or complete output image in memory. Support chunked access beyond individual CLR-array limits where the format permits it. Done when: measured peak memory stays bounded as file size increases, while checksums, layout, metadata and failure guarantees remain correct. Depends on: AV-004, AV-006, AV-012.

  • [ ] AV-014 — Add asynchronous I/O, decode cancellation and progress. Go beyond worker-thread wrappers; propagate cancellation through reads, codecs and writes at documented checkpoints. Keep progress reporting bounded. Done when: cancellation during expensive operations releases resources and preserves existing single-file output; non-interruptible stages are documented. Depends on: AV-003, AV-012, AV-013.

  • [ ] AV-015 — Complete the document lifetime and safe-save model. Provide an explicit fully detached/materialized document operation. Design distributed-XISF staging, recovery and replacement behaviour without promising impossible atomic replacement of two independent files. Done when: deleting the original after detachment cannot break a later save, and failure/cancellation tests cover each distributed publication stage. Depends on: AV-006, AV-013.

Phase 5 — Complete table editing and cross-format fidelity

  • [ ] AV-016 — Add typed FITS table builders and editable serialization. Create and edit ASCII/binary columns and rows, fixed arrays and variable-length heaps. Serialize the edited model rather than requiring callers to construct raw bytes. Done when: create/edit/save/reload tests cover values, units, scaling, nulls, extension metadata, checksums and existing resource budgets.

  • [ ] AV-017 — Complete table shape, null and precision semantics. Interpret TDIM, preserve logical NULL independently of false, and support exact unsigned integer column access where scaling is exactly representable. Done when: independent catalog fixtures cover multidimensional columns, nullable logical values and UInt64 boundaries without hidden precision loss. Depends on: AV-016.

  • [ ] AV-018 — Define preservation-aware document conversion. Specify mappings for tables, array cells, units, global/image properties, extensions, ancillary metadata and astrometry. Use documented preservation extensions where appropriate. Done when: each feature has an explicit preserved/transformed/omitted result; lossy conversion still requires opt-in. Do not promise universal losslessness: standard FITS image HDUs cannot directly represent XISF complex pixels, and not every XISF property/XML structure has a standard FITS counterpart. Depends on: AV-001, AV-004, AV-016, AV-017.

Phase 6 — Broaden astrometry

  • [ ] AV-019 — Support common FITS SIP/TPV distortions. Evaluate forward and inverse transformations with explicit convergence and precision policies. Done when: independent real solutions and reference calculations agree across image centres, edges and difficult inverse cases; unsupported variants fail clearly.

  • [ ] AV-020 — Extend FITS projection and coordinate conventions. Add projections by demonstrated need, axis ordering, angular units, alternate WCS solutions and supported pole parameters. Keep reference-frame conversion explicit. Done when: every advertised convention has independent reference values, domain-boundary tests and documented units/origins. Depends on: AV-019.

  • [ ] AV-021 — Add spectral/time-axis and reference-frame capabilities. Define supported spectral quantities, time scales and celestial frame transformations as separate capabilities. Add table WCS when extending catalog workflows. Done when: supported standards/conventions, required metadata, precision and unsupported cases are explicit and independently tested. Depends on: AV-020; prioritize optical imaging before specialist workflows.

  • [ ] AV-022 — Bridge native XISF and FITS astrometry where representable. Keep their distinct pixel origins and distortion models explicit; never substitute an approximate transform silently during conversion. Done when: supported conversions have coordinate-error bounds and report unrepresentable models without discarding the original solution. Depends on: AV-018–AV-020.

Phase 7 — Add shared image-processing features

These are useful application capabilities, not requirements for reading either format.

  • [ ] AV-023 — Add geometry-aware crop, rotation, resize and reprojection. Update geometry, WCS/native astrometry, CFA and ancillary metadata consistently. Done when: known sky/pixel correspondences remain valid or incompatible metadata is explicitly removed with a diagnostic; scientific pixels remain owned. Depends on: AV-004, AV-012, AV-019–AV-022 as applicable.

  • [ ] AV-024 — Add CFA debayering. Interpret native/FITS CFA metadata and offsets; define initial algorithms, edge handling and output sample precision. Done when: independent mosaics verify orientation, offsets, colour channels, source preservation and metadata updates for both formats. Depends on: AV-004, AV-023 metadata rules.

  • [ ] AV-025 — Extend analysis to cubes and complex data. Add plane/spectrum selection and explicit real/imaginary/magnitude/phase views rather than treating arbitrary axes as colour channels. Done when: shared operations handle these views with correct axes, units, sample precision and missing values. Depends on: AV-004, AV-012, AV-021 where physical axes are evaluated.

  • [ ] AV-026 — Define later scientific-processing modules. Scope calibration, registration, stacking, photometry and plate solving individually before implementing them. Separate display enhancements from scientific measurements. Done when: each selected module has accuracy requirements, provenance rules, independent validation datasets and a focused follow-up checklist. Depends on: shared image access and the relevant geometry/astrometry capabilities.

Phase 8 — Profile and fill specialist coverage

  • [ ] AV-027 — Benchmark remaining allocation hotspots. Measure table-cell boxing, matrix decoding, rectangular-array factories, typed row copies and per-pixel Lab transforms before specializing them. Done when: reproducible before/after throughput and allocation results show a benefit without weakening precision, ownership, checksums or readability. Can proceed alongside earlier phases when real workloads identify a bottleneck.

  • [ ] AV-028 — Add specialist FITS capabilities by demand. Assess random-groups/ UVFITS, compressed tables and other survey/radio conventions separately from common optical-image support. Done when: chosen features appear in the support matrix with independent fixtures and explicit read/write/edit/preservation guarantees. Depends on: AV-001; defer until common image/table workflows are dependable.

Completion rules for every implementation step

  • Preserve existing public contracts or document intentional compatibility changes.
  • Include independent fixtures or reference values as well as round-trip tests.
  • Test corrupt/truncated data, resource limits, precision boundaries and cancellation relevant to the change. Do not use machine-dependent performance assertions.
  • Run relevant checks and Windows/Linux/macOS CI; keep large/private datasets outside Git.
  • Update the support matrix, usage documentation and this checklist with evidence.

Primary references: FITS 4.0, FITS WCS, FITS tile compression, XISF specification.
