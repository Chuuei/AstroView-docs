SIMD acceleration and measurements

AstroView selects CPU implementations at runtime. SIMD improves independent sample operations; it does not replace exact FITS scaling with approximate arithmetic. There are no new native dependencies or CPU requirements.

Operation Accelerated implementation Preserved behavior
XISF byte shuffle and unshuffle AVX2: 32 items; SSE2/Arm64: 16 items Identical bytes, byte planes and incomplete-item tails
Float32 to double Portable 256-/128-bit vector widening Exact finite conversion, byte order, NaN/missing policy
FITS unsigned offsets Bulk byte swapping and vector sign-bit flips UInt16/32/64 boundaries, exact Int64 BLANK comparisons
Integer BLANK scans Vector equality with scalar handling of matching blocks Stored sentinels and physical zero/missing masks
Preview normalization Vector subtraction/division Unclamped values and overflow recovery for extreme bounds
Absolute deviations for median/MAD Vector subtraction/absolute value Same values; selection and statistical reduction order retained

XISF transposes specialize 2-, 4-, 8- and 16-byte items. Other item sizes, short blocks and tails use scalar code. The AVX2 implementation explicitly rearranges 128-bit lanes; AVX2 pack/unpack instructions do not join bytes across those lanes. The Arm64 implementation uses NEON interleaving. Guarded dispatch avoids invoking unsupported instructions. Byte copies, endian reversal, floating-point NaN scans and FITS checksums also benefit from existing runtime/library vector operations.

These choices follow .NET's SIMD and hardware-intrinsic model. The implementation keeps CPU-specific transposes separate from the format parser.

What the workflow benchmark measures

simd-workflows uses 4,194,337 deterministic samples, including NaN and signed zero. It performs three warmups and nine measured operations, using Release builds with tiered compilation disabled. Input construction, garbage collection, normalization buffer resets and complete result hashing are outside the measured interval. Timings and allocation counts are retained for each iteration. Readers run sequentially on an interactive machine with warmed caches; no timing threshold is used in tests.

  • Float32-to-double and unsigned FITS reads start with materialized image storage, then call the production ReadPixels<T> API and allocate owned arrays/masks.
  • Normalization starts with a decoded double array and runs the production stage used by previews. It is not a whole-preview rendering measurement.
  • The shuffled LZ4 read starts with a parsed memory-backed XISF document and calls ReadRawData, including block copying, decompression and unshuffling.
  • The shuffled LZ4 write serializes an image into a new memory stream, including shuffling, compression and final output copying. Checksums are disabled equally in before/after measurements to isolate the codec workflow. Digest verification remains enabled by normal reader/writer policy and covered by regressions.

These are in-memory workflow measurements, not cold-disk or application-startup measurements. Large gains in unsigned reads include eliminating per-pixel generic conversion as well as vectorization. Full-file comparisons remain available in the loading benchmark guide.

Reproduce and verify

dotnet build tools/AstroView.Performance -c Release
$env:DOTNET_TieredCompilation = '0'
dotnet tools/AstroView.Performance/bin/Release/net10.0/AstroView.Performance.dll `
  simd-workflows artifacts/simd-workflows.json

The output path must be fresh. An optional final sample-count argument permits small correctness runs. To exercise fallback dispatch in a fresh process, set DOTNET_EnableAVX=0 or DOTNET_EnableHWIntrinsic=0 before running it. Remove those environment variables to restore normal runtime CPU selection. No setting is required in consuming applications.

Regression tests compare shuffling against an independent byte-by-byte oracle, and sample operations against scalar calculations. They cover unaligned slices, vector boundaries, every partial-item tail, guard bytes, both file byte orders, integer limits, NaN payloads, signed zero and normalization overflow recovery. CI runs ordinary dispatch, no-AVX dispatch and scalar fallbacks on Windows, Linux and macOS. Timings remain evidence, not pass/fail conditions.

Welford statistics and arbitrary exact scaling retain their scalar evaluation order. Branch-heavy histogram bin updates and complete display rendering need separate profiling before further SIMD changes. Broader I/O savings such as partial reads and streaming remain tracked in the roadmap.
