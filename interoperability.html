AstroView

Independent interoperability evidence

Phase 1 adds 60 small independently serialized fixtures and reverse-direction checks using development-only reference tools. The library has no Python, Astropy, or Python XISF runtime dependency.

Committed corpus

tests/AstroView.Core.Tests/Fixtures/Interoperability/manifest.json records producer versions, each file's SHA-256, expected geometry, exact sample values, metadata and independent Astropy WCS reference points. Fixture pixel values and metadata in the original 14 fixtures are original synthetic data. The additional 46 external fixtures retain their source revisions, hashes and MIT notices in the libxisf/ and external/ subdirectories. No telescope photographs are redistributed as part of the local corpus; the committed external samples have their own MIT repository provenance.

Producer Evidence

InteroperabilityTests verifies all file hashes and independently specified pixels/metadata without Python or network access. The independent FITS table exposed and now protects the omitted-repeat-count default in TFORM. Reverse checksum verification also motivated conventional standard-card comment alignment.

LibXisfInteroperabilityTests checks all 40 libXISF files against the upstream generator's deterministic byte pattern, not values derived with AstroView. LocalXisfExampleTests.SmallExternalSamplesMatchIndependentPixelsAndKnownStorageDefects runs six small external cases offline on all three CI platforms. Their independent pixel expectations come from Python xisf for attached images and a separate Python standard-library base64/zlib oracle for embedded images. The manifest records which oracle was used. The two truncated thumbnail cases deliberately require complete saves to fail while leaving their primary images accessible.

Reverse-direction checks

tools/AstroView.Interop writes one checksummed FITS image and five XISF images, one per codec including uncompressed. Astropy and Python xisf read these exports and compare known pixels and metadata. Astropy additionally verifies FITS checksums. CI performs these checks separately from the three-platform offline .NET suite. It also checks all 40 original libXISF files and AstroView's preserving rewrites against the independent producer pattern using Python xisf.

python -m pip install setuptools==84.2.1 wheel==0.48.0
python -m pip install --no-build-isolation -r tools/interop/requirements.txt
dotnet run --project tools/AstroView.Interop -c Release -- artifacts/interop/exports
python tools/interop/fixtures.py verify
python tools/interop/xisf_samples.py verify-fixtures
python tools/interop/xisf_samples.py verify-fixtures --directory artifacts/interop/exports/libxisf

Use an isolated virtual environment for the Python tools. To intentionally regenerate the committed corpus, run python tools/interop/fixtures.py generate and review both binaries and manifest changes. Producers write creation times and checksum comments, so regeneration can change byte hashes without changing pixels. Expected values come from generator input, not from decoding with AstroView.

The pinned tools retain their own licenses: Astropy is BSD-3-Clause, Python xisf is GPL-3.0, NumPy is BSD-3-Clause, and their codec dependencies retain their own notices. No source from those tools is copied into AstroView or its NuGet package. Running a separate development tool does not make it a library dependency. The synthetic fixture data have their own redistribution notice alongside the manifest.

Local photographs and real producer files

Fixtures/LocalXisf/manifest.json records provenance, original file hashes and independent pixel hashes for 73 local XISF files containing 79 primary images (2,739,639,831 original file bytes). The images remain outside Git at C:\Code\AstroExamples\XISF. Python xisf decoded 75 images; four embedded images were checked separately with the standard-library oracle. All 79 match AstroView's decoded bytes. The existing 11 local FITS files remain separate.

The opt-in local XISF test verifies every original hash, geometry, sample type, layout and independently decoded pixel hash. It then saves/reloads the 71 complete files, compares the independent pixel expectations again and checks preservation of the original XML metadata, allowing changed attachment offsets and added block digests. Twelve files contain legacy PCL:AstrometricSolution:* metadata, which survives that save path. These tests prove preservation, not coordinate evaluation. All attached serialized blocks are also hashed directly from the original and rewritten files, including thumbnails and binary property matrices/vectors. The two incomplete samples must reject thumbnail access and complete saving.

Semantic validation diagnostics remain in the optional local report. Existing files trigger findings for missing explicit UTF-8 declarations, legacy creation time typing and ICC flags. Pixel compatibility does not mean strict conformance. See testing for commands and report paths. Regenerate independent expectations explicitly, then review the manifest diff:

python tools/interop/xisf_samples.py record-local --corpus C:/Code/AstroExamples/XISF
python tools/interop/xisf_samples.py import-fixtures --corpus C:/Code/AstroExamples/XISF
python tools/interop/xisf_samples.py import-embedded --corpus C:/Code/AstroExamples/XISF

The local sample provenance is documentation of public availability and stated usage terms, not permission to redistribute the photographs. Only small fixtures distributed by MIT repositories are committed, with their notices.

Coverage gaps — AV-002 remains partial

The new corpus is independent evidence for the combinations above, not a claim of universal producer compatibility or complete XISF conformance. In particular:

  • No independently produced real native XISF astrometric/distortion solution with confirmed redistribution permission is available in the current corpus.
  • Independently produced distributed XISF, XISF tables, complex/UInt64 pixels, big-endian and interleaved files are not yet represented. Python xisf's writer does not cover all of these capabilities. Existing generated .NET tests remain useful regressions but do not close the independent-producer evidence gap.
  • Python xisf 0.9.7 fails on embedded image data (KeyError: value); embedded images are therefore excluded from its reverse-reader checks. AstroView's embedded-image tests are separate; the reference tool is not patched to pass.
  • Native astrometry must not be confused with the legacy PCL: properties in twelve local files. No local file has a native AstrometricSolution:* solution.

AV-001 and AV-003 can be completed independently. AV-002 stays unchecked until the remaining independently produced fixtures, provenance/permissions, and reference expectations are collected. Add files and tests incrementally without relabeling AstroView-generated fixtures as independent producer data.

Reference implementations: Astropy FITS, Astropy WCS, Python xisf.
