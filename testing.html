AstroView

Testing FITS and XISF

The solution also includes desktop workflow and rendering checks for the Avalonia application. They run headlessly on all three CI platforms and keep GUI dependencies out of the Core project. Large desktop corpus checks are separately opt-in with ASTROVIEW_DESKTOP_EXAMPLES.

Portable regression suite

dotnet restore AstroView.sln --locked-mode
dotnet build AstroView.sln -c Release --no-restore
dotnet test AstroView.sln -c Release --no-build --collect:"XPlat Code Coverage"

CI runs the same suite and package build on Windows, Linux, and macOS. Generated fixtures require no network or photograph corpus. Tests exercise:

  • Independent FITS/XISF bytes, truncated headers/payloads/padding, invalid UTF-8, malformed text encodings, unsupported headers, DTD rejection, and resource limits.
  • FITS empty HDUs, zero-sized axes, floating-point special values, big-endian storage, scaling, integer BLANK, unsigned boundaries, and variable-array heap bounds.
  • Every XISF codec/checksum combination in both byte orders, shuffle/subblock tails, planar/interleaved channels, and deliberate payload corruption before decompression.
  • One-byte and short reads through seekable/non-seekable streams, sync/async APIs, exact buffering limits, stream ownership, Unicode filenames, atomic replacement, and invariant parsing under German, French, and Turkish cultures.
  • Existing metadata, conversion, rendering, cancellation, and signature regressions.

These checks establish behaviour on the tested runners, not universal support for all operating systems, architectures, or file variants. Tests do not contact external URLs. The local corpus is not uploaded to GitHub.

Local example corpus

The corpus test is explicitly skipped unless ASTROVIEW_EXAMPLES is set. A configured missing/empty directory fails rather than silently passing. Run it separately because the photographs can require hundreds of MB per document:

$env:ASTROVIEW_EXAMPLES = 'C:\Code\AstroExamples'
$env:ASTROVIEW_EXAMPLE_REPORT = "$PWD\artifacts\local-examples\report.json"
$env:ASTROVIEW_XISF_EXAMPLE_REPORT = "$PWD\artifacts\local-examples\xisf-report.json"
dotnet test AstroView.sln -c Release --filter Category=LocalExamples
Remove-Item Env:ASTROVIEW_EXAMPLES
Remove-Item Env:ASTROVIEW_EXAMPLE_REPORT
Remove-Item Env:ASTROVIEW_XISF_EXAMPLE_REPORT

On Linux/macOS use ASTROVIEW_EXAMPLES=/path/to/images dotnet test AstroView.sln -c Release --filter Category=LocalExamples (on one line). The report path is optional. Reports belong under ignored artifacts/.

The local test recursively checks .fits, .fit, and .fts files, one at a time, without modifying them. It independently scans physical header cards to compare image axes and BITPIX, checks the payload sizes, compares SHA-256 of every loaded payload byte against the original file, verifies present checksums, and requires no error-level diagnostics or unread trailing bytes. Missing checksums are accepted and do not establish integrity. The report records filenames, lengths, payload hashes, failures, OS, runtime, and process architecture.

This validates loading/storage fidelity, not image aesthetics or independently calibrated pixel/astrometric correctness. The supplied corpus currently contains 11 FITS files plus 73 downloaded XISF files containing 79 primary images. The XISF test checks the committed Fixtures/LocalXisf/manifest.json against files in the XISF subdirectory (or the configured directory itself). Every listed file must exist and match its original SHA-256. Independent reference hashes come from the pinned Python reader or the separately identified base64/zlib oracle. The test checks pixels/geometry/layout/types, then saves/reloads the 71 complete files in a temporary directory and compares all pixels and preserved XML metadata. Two sources have missing thumbnail attachments: their primary pixels are checked, but thumbnail access and complete saving must fail. Source files are never edited.

Set ASTROVIEW_XISF_EXAMPLE_REPORT to record per-file results and semantic diagnostics separately from the FITS report. Successful pixel decoding does not require these legacy producer files to pass strict semantic validation. The large local corpus has been exercised on Windows; the 60 small committed independent fixtures run on Windows/Linux/macOS CI. No external images enter the package.

Review and performance measurements

See the code review for resolved findings, compatibility changes, remaining limitations, and the median/MAD benchmark. Run the benchmark with dotnet run --project tools/AstroView.Performance -c Release. It checks result equivalence and reports timing/allocation measurements; CI does not assert machine-dependent timing thresholds.

The file-load benchmark compares AstroView with Astropy and Python xisf using validated pixel/mask hashes. CI runs a tiny fixture smoke comparison and report-contract tests; timing values are diagnostic and never CI thresholds.
