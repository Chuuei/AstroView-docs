Metadata and tables

Property scopes

XISF distinguishes document properties, image properties and creation metadata. XisfDocumentData.Properties contains global values; Images[i].Properties contains values for that image; Metadata contains XISF creation metadata. Creation identifiers must start with XISF:. Put application-defined data in your own property namespace instead of inventing creation keys.

Property identifiers are case-sensitive. Known property definitions in XisfKnownProperties and XisfAdditionalProperties expose typed keys and provenance through MetadataDefinitionSource. Standardized identifiers and PixInsight/PCL conventions have distinct meanings and provenance; do not treat every catalog entry as part of the XISF standard.

XisfPropertyCollection accepts supported CLR values, explicitly typed XisfPropertyData, or preserved parsed properties. Use a typed key where one is available. Explicit type information is useful for vector/matrix values and when an exact serialized type is part of an interchange contract.

Create a document property and table

public static void MetadataAndTables(string directory)
{
    var loaded = XisfReader.Load(Path.Combine(directory, "image.xisf"));
    var editable = loaded.ToEditable();
    editable.Properties["Example:Session"] = "Night 1";
    editable.Images[0].Properties.Set(XisfKnownProperties.Observation.Object.Name, "M31");
    var table = new XisfTableData { Id = "Stars", Caption = "Reference measurements" };
    table.Fields.Add(new XisfTableFieldData("Name", "String"));
    table.Fields.Add(new XisfTableFieldData("Flux", "Float64"));
    table.Rows.Add(new object?[] { "Star A", 1234.5 });
    editable.Tables.Add(table);
    string output = Path.Combine(directory, "catalog.xisf");
    XisfWriter.Write(output, editable);
    if (XisfReader.Load(output).Tables.Count != 1)
        throw new InvalidOperationException("Table round trip failed.");
}

The example creates a document-level table. XisfImageData.Tables can instead attach tables to a particular image. Each row must match the field count, and cell CLR values must match their declared types. Numeric vectors and rectangular matrices are distinct from scalar cells. Use the API reference for field, row and cell models rather than relying on displayed table text.

Parsed availability and opaque content

Parsed XisfProperty and table-cell values can be unavailable while their XML remains preserved. Check IsAvailable and UnavailableReason before computing with the value. An absent property, an unavailable value and a value of zero are different states. Do not replace an unavailable value with zero or an empty string merely to simplify a UI.

Array-valued parsed properties return owned copies. Changing an array returned by Value does not edit the original document. Use an editable collection or an explicit XML edit and retain its returned document.

ToEditable() materializes images but can still retain source-aware opaque objects. Keep source blocks available through saving if opaque metadata is present. Choose the native parsed writer when preserving unfamiliar content is more important than changing the serialization strategy.

FITS keywords

FITS headers are ordered cards with case-insensitive keyword lookup. FITS cards stored inside XISF use XisfFitsKeyword, including text quoting conventions. XisfFitsKeyword.FromValue quotes and escapes strings correctly and handles commentary cards. Prefer it to building quoted text manually, particularly for object names containing apostrophes or slash characters.

FITS keywords inside an XISF image are a metadata representation. They do not become native FITS HDUs until an explicit conversion. Conversely, an XISF property is not automatically representable as a FITS card. Conversion findings identify known omissions and transformations.
