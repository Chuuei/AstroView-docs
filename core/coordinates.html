Coordinates and astronomy

FITS WCS and native XISF astrometry are separate models

CelestialWorldCoordinateSystem.TryCreate accepts a FITS header or XISF FITS keywords. It supports recognized degree-based RA/Dec TAN WCS and supported legacy linear metadata without CTYPE. It does not evaluate every projection, frame, axis permutation or distortion convention found in a FITS header.

Check the Boolean result before calling PixelToSky or SkyToPixel. A retained WCS card can be unsupported for evaluation. An unsupported model should produce an explicit unavailable-coordinate state in your application rather than falling back to an unrelated transform.

XisfAstrometricSolution uses native AstrometricSolution: properties. It exposes an available layer and diagnostics, supports seven native projections and can evaluate supported projective/distortion layers. PCL/legacy property namespaces are not automatically relabeled as a native solution.

Coordinate conventions

API Image position convention Sky angles
FITS PixelToSky / SkyToPixel Zero-based pixel centres; the API adapts FITS CRPIX RA/Dec in degrees
Native XISF ImageToCelestial / CelestialToImage Pixel centres at half-integers: first pixel is (0.5, 0.5) RA/Dec in degrees
Desktop Coordinates workspace Zero-based centres for both source models RA/Dec in degrees

Do not add a FITS one-pixel offset before passing a zero-based position to PixelToSky. Do add the native half-pixel offset when adapting a zero-based pixel centre to the native XISF model. Conversely, subtract 0.5 from a native XISF image position when presenting zero-based pixel coordinates.

Right ascension is an angle in degrees, not hours or an hh:mm:ss string. Convert an hour value by multiplying by 15 before calling these APIs. Declination must be within the model's supported angular domain. An inverse transform can throw when the sky position lies outside the projection's valid area.

Create and check a native solution

public static void Coordinates()
{
    var solution = XisfAstrometricSolution.CreateLinear(
        "Gnomonic", [83.633, 22.0145], [512.5, 384.5],
        new double[,] { { -0.0003, 0 }, { 0, 0.0003 } });
    // Native XISF pixel centres are half-integers: (0.5, 0.5) is the first pixel.
    var sky = solution.ImageToCelestial(512.5, 384.5);
    var pixel = solution.CelestialToImage(sky.RightAscension, sky.Declination);
    if (Math.Abs(pixel.X - 512.5) > 1e-6 || Math.Abs(pixel.Y - 384.5) > 1e-6)
        throw new InvalidOperationException("Astrometry round trip failed.");
    Console.WriteLine($"RA {sky.RightAscension}°, Dec {sky.Declination}°");
}

Supported projection identifiers are Gnomonic, Stereographic, ZenithalEqualArea, Orthographic, PlateCarree, Mercator and HammerAitoff. The reference celestial coordinates and linear matrix use degrees and degrees per pixel. Matrix signs determine orientation; a negative horizontal term is common when right ascension increases toward the left.

Use ApplyTo(editableImage) to write the solution's native properties. If a geometric operation changes an image in a way that cannot preserve its solution exactly, use RemoveFrom instead of retaining invalid astrometry. Display zoom and pan do not change image geometry; resampling/cropping in your own processing pipeline does.

Work with loaded solutions

Inspect image.AstrometricSolution, AvailableLayer and Diagnostics. A non-null object can carry metadata that is not fully evaluable. Do not infer availability solely from the presence of one property. Create validates a new property set more strictly; use it when constructing a complete solution.

Test both the reference point and off-centre points. A forward/inverse round trip catches coordinate-convention mistakes but is not independent scientific validation: the same incorrect model can invert itself consistently. Use independent reference coordinates for accuracy-sensitive applications.

Observation metadata

AstronomyMetadata reads recognized XISF properties or FITS headers into AstronomyImageMetadata for values such as object, instrument, exposure and filter. Missing values remain optional. It does not perform plate solving, source detection, time-scale conversion or ephemeris computation. Consult the support matrix for the exact evaluated conventions.
