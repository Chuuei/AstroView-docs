Working with FITS

Documents, HDUs and headers

FITS files are ordered sequences of header/data units (HDUs). Load a document with FitsReader.Load or its async overloads. Preserve the document's HDU order, including a primary HDU that may contain no image. document.Images is a convenience image sequence, not a replacement for the full HDU collection.

FitsHdu.Content can expose a decoded FitsImage, FitsTable or no interpreted content. Unknown extensions can retain raw payloads. Header is an ordered collection of FitsHeaderCard records, so repeated cards and comments can be represented. Do not replace it with a dictionary if preservation matters.

Use Set for a single-valued keyword and Add for repeated HISTORY or COMMENT records. FitsKnownKeywords and FitsKeywordKey<T> provide typed definitions for supported standard and convention-specific keywords.

Create, write and verify an image

public static void CreateFits(string directory)
{
    ushort[] pixels = [0, 100, 200, 65535];
    var image = FitsImage.FromPhysicalSamples(pixels, [2, 2]);
    var hdu = FitsHdu.CreateImage(image, primary: true);
    hdu.Header.Set("OBJECT", "M31");
    hdu.Header.Add(new FitsHeaderCard("HISTORY", null, "Created with AstroView.Core"));
    string path = Path.Combine(directory, "image.fits");
    FitsWriter.Write(path, new FitsDocument([hdu]), new() { WriteChecksums = true });
    var loaded = FitsReader.Load(path);
    double[] physical = loaded.Images.First().GetPhysicalSamples();
    if (!physical.SequenceEqual(pixels.Select(value => (double)value)))
        throw new InvalidOperationException("FITS sample round trip failed.");
    if (loaded.Hdus[0].ChecksumValid != true || loaded.Hdus[0].DataChecksumValid != true)
        throw new InvalidOperationException("FITS checksums failed.");
}

FromPhysicalSamples chooses appropriate FITS storage for supported input types, including conventional unsigned offsets. GetPhysicalSamples applies stored scaling and blank handling. Creating a primary image uses primary: true; additional image extensions use false after a valid primary HDU.

FitsWriterOptions.WriteChecksums is false by default. Set it to true when you want the writer to generate CHECKSUM and DATASUM. After loading, checksum results are nullable: missing, valid and invalid are different states.

Exact 64-bit values

Physical double access can round large integer samples. For supported unsigned offset storage, use the typed conversion path and keep the result in ulong.

public static void ExactIntegers()
{
    ulong[] pixels = [0, 1, 9007199254740993UL, ulong.MaxValue];
    var hdu = FitsHdu.CreateImage(FitsImage.FromPhysicalSamples(pixels, [2, 2]), primary: true);
    using var stream = new MemoryStream();
    FitsWriter.Write(stream, new FitsDocument([hdu]));
    stream.Position = 0;
    var fits = FitsReader.Load(stream);
    var converted = FitsConverter.ConvertToXisf(fits);
    ulong[] exact = converted.Value[0].GetSamples<ulong>();
    if (!exact.SequenceEqual(pixels))
        throw new InvalidOperationException("Exact UInt64 conversion failed.");
    // GetPhysicalSamples() returns double and cannot retain all these integers.
}

This demonstrates a specific supported storage convention, not a promise that arbitrary Int64 FITS scaling can always be represented exactly in XISF. XISF has unsigned integer image formats, and signed/scaled FITS conversions can use a floating-point path or fail when exact representation is not available. Treat NotSupportedException as an explicit unsupported conversion.

Structural edits

Headers contain structural cards tied to payload geometry and storage, including BITPIX, NAXIS*, scaling and table layout cards. Editing such a card does not resize or reinterpret the payload safely. Use ReplaceImage to replace an image through the native model, or deliberately construct a new HDU.

Core guards inconsistent structural edits when writing. Application code should offer a specific image-replacement operation rather than exposing every header card as an unrestricted text field. Use native document output to retain uninterpreted extensions; conversion is a separate, potentially lossy operation.

FITS tables

Parsed ASCII and binary tables expose Columns and Rows. Column metadata includes format, units, scale, zero point and null conventions. Values can be arrays or exact integer types, so avoid stringifying every cell if subsequent computation or round-trip fidelity matters.

The native table model is read-only. Preserve the containing HDU when retaining original table storage. Conversion to XISF can transform tables and report loss of original storage/extension details; it is not a native FITS table editor. See metadata and tables.

Validation and unsupported conventions

FitsValidationMode.Tolerant records supported conformance findings and is the default. Strict rejects error-level findings. Neither mode enables a missing codec or convention. Image decompression for tiled/compressed FITS and broader WCS evaluation remain roadmap items.

Retaining a header containing SIP, TPV or another WCS convention does not make that convention evaluable by CelestialWorldCoordinateSystem. Always check TryCreate before using a coordinate transform. Consult coordinates, reader budgets and the support matrix for supported operations and limits.
