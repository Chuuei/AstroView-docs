Rendering and analysis

Scientific samples, display pixels and measurements serve different purposes. Choose the representation deliberately and preserve the original scientific samples when producing a preview.

Render a display image

XisfDisplayRenderer.Render accepts a parsed or editable image. It returns an XisfBgra32Image: dimensions, DPI and owned BGRA pixels with straight alpha. The output is suitable for a graphics adapter but is not an encoded PNG/JPEG. Choose an image encoder in your application if you need a preview file.

Stretch argument Behavior
null Linear normalization for display
XisfStretchOptions.Auto Adaptive display stretch with linked channels by default
XisfStretchOptions.DisplayFunction Uses a stored display function where applicable
New XisfStretchOptions Configure target background, shadow clipping, channel linking and stored-function use

The Core automatic stretch defaults to target background 0.25 and shadow clipping -2.8. The desktop chooses 0.22 for its initial preview. Do not assume that every caller uses the same application-level defaults.

The renderer supports supported two-dimensional real images and interprets orientation, relevant color metadata and alpha. Complex magnitude/phase display and a general scientific cube-plane renderer are not implemented. Read those samples through the scientific APIs instead.

Statistics, histogram and region example

public static void AnalyzeAndRender(string directory)
{
    var image = XisfReader.Load(Path.Combine(directory, "image.xisf")).Images[0];
    var statistics = image.CalculateStatistics(new()
    {
        Normalize = false,
        MaximumSamplesPerChannel = 100_000
    });
    var histogram = image.CalculateHistogram(channel: 0, binCount: 256,
        lowerBound: 0, upperBound: 65535);
    ushort[] region = image.ReadRegion<ushort>(0, 0, 2, 1);
    var preview = XisfDisplayRenderer.Render(image, XisfStretchOptions.Auto);
    Console.WriteLine($"Mean: {statistics[0].Mean}; preview: {preview.Width} × {preview.Height}");
    if (histogram.Bins.Sum() != 4 || !region.SequenceEqual(new ushort[] { 0, 100 }))
        throw new InvalidOperationException("Analysis example failed.");
    // preview.Pixels is BGRA32 display data. It is not a PNG file.
}

ReadRegion<T> returns all image channels in the requested layout. To read a whole channel, use ReadChannel<T>(channel). Region coordinates are zero-based; width and height must be positive and remain within a two-dimensional image. The region method still decodes the complete source block before extracting the requested rectangle.

Interpret measurements correctly

CalculateStatistics returns one XisfChannelStatistics per channel. It exposes sampled count, finite/non-finite counts, extrema, mean, standard deviation, median and median absolute deviation (MAD). MaximumSamplesPerChannel defaults to 1,000,000 in Core. Sampling can miss an isolated extreme or rare invalid value; these statistics are not guaranteed full-image extrema when sampling occurs.

Normalize = true expresses measurements relative to declared image bounds. It is independent of display stretching. Values outside declared bounds can remain outside the normalized interval rather than being silently clamped. Median/MAD and other measurements use floating-point representations, so very large integer values can round.

Histograms examine every sample in one chosen channel. The result separates in-range bin counts, underflow, overflow and non-finite counts. A histogram's bin sum alone is not necessarily the total number of pixels: include the other counts when checking totals. Bounds use scientific values, not automatically the units shown in a normalized statistics table or stretched preview.

Do not derive a scientific histogram from 8-bit preview pixels. That would measure the display transformation rather than the source image.

Color and display utilities

XisfColorSpace provides RGB ↔ XYZ, RGB ↔ Lab and grayscale/luminance operations. Its default working space is D50-adapted sRGB. XisfDisplayFunctions contains display/midtones utilities. Specify a supported working space when a file's metadata requires a different interpretation.

These transforms are not a full ICC engine, an image calibration workflow or a general photometry package. AstronomyMetadata and coordinate models provide specific metadata/astrometry support; broader astronomical algorithms should be documented separately as they are added.

Memory and UI integration

A BGRA preview requires roughly four bytes per output pixel in addition to source/decompressed data. Typed reads allocate arrays; normalization adds double buffers. Avoid retaining several previews and sample copies for every open large document. Perform expensive rendering and analysis away from your UI thread, then transfer owned output to your UI framework. Read resource policy and performance for practical limits.
