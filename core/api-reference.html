AstroView

Core API reference guide

The HTML documentation includes a generated reference for the public AstroView.Core API: types, constructors, overloads, signatures, generic constraints, properties, enum values, parameter descriptions, return values and declared exceptions. It is generated from the built Core assembly plus the same XML documentation distributed next to AstroView.Core.dll.

In the HTML edition: browse the complete API namespace. Use the API navigation filter or site search for an exact type or member name. When reading on GitHub: use the type map below, the source tree, or build the HTML edition. Generated API pages are build output rather than checked-in copies of the implementation.

Reading an API page

  1. Check whether the type represents parsed content, editable content or an operation/result. That distinction governs source lifetimes and fidelity.
  2. Choose an overload deliberately: paths, caller streams, parsed documents, editable documents and image sequences have different contracts.
  3. Read the default values in the signature and the XML remarks. In particular, sample layout, loss rejection, checksum generation and lazy access defaults affect integration behavior.
  4. Follow parameter/return-type links for option and result structures.
  5. Consult the conceptual guide for context; a type page cannot define your application's resource, identity-trust or fidelity policy.

API generation is part of documentation CI and uses warnings as errors. Update public XML comments with code changes; rebuild the reference rather than editing generated HTML/YAML. Follow documentation maintenance when adding types or recipes.

Shared scientific access (0.3.0 development)

AstroFile, AstroFileOptions, AstroFileFormat, FitsHduInfo and AstroImageInfo provide content detection, metadata indexing and selected native access. IImageSource, ImagePixels, ImageDescriptor, PixelBuffer<T>, PixelReadOptions, PixelValueKind, PixelConversionMode, ImageSampleType and ImagePixelLayout define exact typed reads and masks. See the access guide for precision, lifetime, security and memory contracts. All public members are included in the generated API reference.
