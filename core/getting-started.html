AstroView

Installation and quick start

Requirements

Use a .NET 10 SDK to build an application against AstroView.Core. The library itself needs .NET 10 at runtime. It has no graphical subsystem requirement. Nullable reference types and implicit usings are enabled in the sample project.

Choose one of the following consumption methods. Use the actual version from your release or locally built package rather than assuming that a version has already been published to nuget.org.

Method Setup Dependency handling
Project reference Reference src/AstroView.Core/AstroView.Core.csproj from another project Normal NuGet restore of Core's dependencies
Local NuGet source Extract the Core release; add its nuget directory as a package source NuGet restores the compression and cryptography packages
Direct DLL reference Extract the complete Core ZIP; import AstroView.Core.props The import references and copies the supplied DLLs

For a local package source:

dotnet new console --framework net10.0 --name MyAstroTool
dotnet nuget add source /absolute/path/to/extracted/nuget --name AstroViewLocal
dotnet add MyAstroTool package AstroView.Core --version 0.2.0

Replace 0.2.0 with the package's version, including its prerelease suffix if present. Keep nuget.org enabled so package dependencies can restore.

For the direct DLL method, add this after your target framework property group:

<Import Project="path/to/extracted/AstroView.Core.props" />

Retain the archive's directory structure. The reference file selects the proper cryptography implementation for the target, including cross-publishing. Avoid mixing these direct references with different versions of the same NuGet dependencies. See the Core archive README and release guide.

Create an image

The recipe below uses using AstroView.Core;. Its directory argument is a writable output directory created by the caller. Dimensions are width then height; one channel means a monochrome image. FromSamples copies the input.

public static void CreateXisf(string directory)
{
    ushort[] pixels = [0, 100, 200, 65535];
    var image = XisfImageData.FromSamples(pixels, [2, 2], 1);
    image.Id = "Luminance";
    image.Properties.Set(XisfKnownProperties.Observation.Object.Name, "M31");
    image.FitsKeywords.Add(XisfFitsKeyword.FromValue("EXPTIME", 180.0, "Seconds"));
    XisfWriter.Write(Path.Combine(directory, "image.xisf"), [image], new()
    {
        Compression = XisfCompression.Zstd,
        Shuffle = true,
        Checksum = XisfChecksum.Sha256
    });
}

This creates a 2 × 2 UInt16 XISF image with Zstandard compression, byte shuffle, a SHA-256 block digest, an object name and an exposure keyword.

Read it back

public static void ReadXisf(string directory)
{
    var document = XisfReader.Load(Path.Combine(directory, "image.xisf"));
    var image = document.Images[0];
    ushort[] pixels = image.GetSamples<ushort>();
    Console.WriteLine($"{image.Dimensions[0]} × {image.Dimensions[1]}, {image.ChannelCount} channel(s)");
    if (!pixels.SequenceEqual(new ushort[] { 0, 100, 200, 65535 }))
        throw new InvalidOperationException("XISF sample round trip failed.");
}

Load parses the document. GetSamples<ushort>() forces the selected image's data to decode and verifies any declared block checksum. The returned array is owned by your application. Mutating it does not update the parsed image.

Run all examples

From the repository root:

dotnet run --project examples/AstroView.Core.Examples -c Release -- artifacts/my-examples

The executable creates its own small FITS/XISF files and checks the results. It does not require downloaded astronomical photographs. Subsequent runs reuse the chosen output directory, so choose a dedicated example directory.
