Indexed opening and typed scientific pixels

These APIs are available in 0.3.0 development builds. The published 0.2.0 release predates Phase 2. Existing native readers and converters remain available; no existing method was removed. New applications can use AstroFile for discovery and IImageSource for operations shared by FITS and XISF.

Open by content and select an image

AstroFile.Open inspects signatures instead of filename extensions. It recognizes FITS primary headers, monolithic XISF and distributed XISF XML headers. It reports gzip as a recognized transport and throws a specific NotSupportedException when opening it; gzip FITS support is AV-008. Unknown content also throws NotSupportedException. Recognized malformed headers throw FitsFormatException or XisfFormatException.

public static void IndexedAccess(string directory)
{
    foreach (string name in new[] { "image.fits", "image.xisf" })
    {
        using var file = AstroFile.Open(Path.Combine(directory, name));
        AstroImageInfo entry = file.Images[0];
        Console.WriteLine($"{file.Format}: {entry.Descriptor!.SampleCount} samples");
        IImageSource source = entry.OpenImage();
        PixelBuffer<ushort> pixels = source.ReadPixels<ushort>();
        if (!pixels.Samples.SequenceEqual(new ushort[] { 0, 100, 200, 65535 }))
            throw new InvalidOperationException("Shared typed read failed.");
        if (source.NativeImage is FitsImage fits)
            Console.WriteLine($"Native FITS BITPIX: {fits.BitPix}");
        else if (source.NativeImage is XisfImage xisf)
            Console.WriteLine($"Native XISF properties: {xisf.Properties.Count}");
    }
}

The same typed operation consumes either format without converting the document or passing integer pixels through double. NativeImage exposes the original FitsImage, XisfImage or XisfImageData. For an existing native image, call ImagePixels.From(image). FitsImage.ReadPixels<T>() is a convenience entry point to the same implementation.

Images lists discoverable native images. NativeIndex is the FITS HDU index or the XISF image index; it can differ from the position in Images. Unsupported XISF sample types remain indexed with a null Descriptor and an UnsupportedReason; opening them throws XisfUnsupportedFeatureException. Image processing utilities still have their existing XISF-oriented APIs. The shared view is a scientific access contract, not a replacement rendering engine.

Geometry, layout and numeric meaning

ImageDescriptor.Dimensions contains width first, then height and further scientific axes. FITS axes are preserved with one channel; a third axis of length three is never silently interpreted as RGB. XISF channels remain separate from its spatial/scientific dimensions. SampleCount includes channels and counts each complex pair as one sample. Axis lengths and sample counts are 64-bit in the index; native materialization is still constrained by supported CLR arrays.

StoredType, IsBigEndian and Layout describe the native samples. Output arrays use host byte order. PixelReadOptions.Layout selects planar (the default) or interleaved output. For two RGB pixels these orders are R0 R1 G0 G1 B0 B1 and R0 G0 B0 R1 G1 B1. A missing-value mask follows the same permutation.

Values = Physical applies FITS physical = stored * BSCALE + BZERO. Stored returns raw numeric samples after byte-order decoding, retaining BLANK sentinel values. XISF values are its native scientific values: bounds, display functions, pedestal metadata and color transforms are not applied by this API.

Exactness, rounding and undefined values

public static void TypedMissingValues()
{
    var fits = FitsImage.FromRaw(new byte[] { 0, 1, 2 }, 8, [3, 1],
        bScale: 0.5, bZero: 1, blank: 2);
    PixelBuffer<decimal> physical = fits.ReadPixels<decimal>();
    if (!physical.Samples.SequenceEqual(new[] { 1m, 1.5m, 0m }) || !physical.Missing[2])
        throw new InvalidOperationException("Scaled values or missing mask failed.");
    PixelBuffer<byte> stored = fits.ReadPixels<byte>(new() { Values = PixelValueKind.Stored });
    if (stored.Samples[2] != 2 || !stored.Missing[2])
        throw new InvalidOperationException("Stored BLANK sentinel was not retained.");
    // Physical integer reads must opt into truncation when fractions are present.
    var rounded = fits.ReadPixels<int>(new() { Conversion = PixelConversionMode.Checked });
    if (rounded.Samples[1] != 1) throw new InvalidOperationException("Explicit truncation failed.");
}

Conversion = Exact is the default. A finite sample that cannot be represented exactly in the destination raises ArithmeticException; out-of-range values raise OverflowException. Use a matching integer type to retain UInt64 values above 2^53. The unsigned FITS offset conventions use integer operations, including BZERO = 2^63. Parsed Int64-valued scaling cards are retained exactly for typed reads and FITS output, even when their approximate BScale/BZero double properties cannot express their low bits. Floating-point scaling coefficients use their parsed binary64 values, not exact decimal arithmetic on header text. Arbitrary scaling uses exact rational arithmetic to avoid intermediate rounding or cancellation. A decimal result is accepted only when it represents that physical value exactly; binary64 0.1, for example, is not decimal 0.1.

Checked explicitly allows floating-point rounding and integer truncation toward zero. It still rejects overflow, including a finite binary64 value overflowing to binary32 infinity. It never clamps or wraps integers. General scaled floating conversion uses a binary64 approximation; use Exact when scientific precision must be guaranteed. Unscaled matching types use direct byte copies rather than per-sample rational arithmetic.

PixelBuffer<T>.Missing marks integer BLANK and NaN values. Infinity is valid unless scaling makes it NaN. Physical BLANK/real NaN becomes NaN in floating-point outputs and zero in integer/decimal outputs; the mask remains authoritative. Stored reads retain integer sentinel values. Complex images require System.Numerics.Complex; both component values are retained, and either NaN component marks the sample missing. Complex32 components expand exactly to binary64. Arrays and masks belong to the caller; changing them does not edit the native image.

The older GetPhysicalSamples() remains a convenient, explicitly approximate double API. Migrate precision-sensitive code to ReadPixels<T>(); migrate explicitly approximate calculations to Conversion = Checked.

What a metadata-only scan reads

  • FITS: padded header cards for every HDU, native type, geometry, data offsets, payload lengths and header diagnostics. Payloads and data padding are skipped with seeks. Empty HDUs, tables and unknown extensions remain in FitsHdus.
  • XISF: the bounded XML header, image geometry and original location/compression attributes. Property blocks, table cells, ICC blocks and image pixels are not fetched or decoded during indexing. Inline/embedded encoded data is part of the XML header itself and counts toward the header budget. XisfHeader is a detached XML copy that retains global metadata, unknown extensions and block descriptors.

AstroFileOptions.MaximumMetadataBytes defaults to 64 MiB across all FITS headers or the XISF XML header. Native header/count/geometry security budgets also apply. Selected-payload byte budgets apply when content is requested, so a FITS index can describe an image larger than the configured materialization limit. Each selected HDU must fit MaximumDataSize and MaximumTotalDecodedBytes; this is not a cumulative limit on buffers the caller chooses to retain across repeated reads. Keep full scientific images within your application's memory budget.

ReadFitsHdu(nativeIndex) loads just one native HDU, validates its checksums and padding, and decodes its supported image/table content. ReadFitsDocument() explicitly reads every HDU. ReadXisfDocument() parses the full native XML model and decodes its properties/tables; image pixels remain lazy. Merely opening an index does not validate data checksums, decode codecs, or prove that external resources exist. A corrupt unrelated payload does not prevent selected access.

Source ownership and changes

Dispose an index with using. Path opening owns a read-only file handle. Stream opening requires readable, seekable input at position zero and defaults to leaveOpen: true. Input is not copied wholesale; non-seekable callers can still use the existing native reader APIs with their buffering budgets. Failed opening leaves caller streams open and restores their position. Successful indexed reads also preserve the shared stream position. Detection alone preserves its starting position and inspects at most 64 KiB; XML roots following larger prologs are not recognized by the detector.

Keep path sources available and unchanged. The index checks the main file's size and last-write time before/after selected native reads and before lazy XISF block reads. On Windows, the read-sharing mode additionally prevents ordinary writes while the index owns the handle. These checks are not cryptographic snapshots; same-size edits with a restored timestamp cannot be guaranteed detectable. Caller-owned streams must not be edited or used concurrently; length changes are detected, same-length edits are the caller's responsibility.

Local external XISF resources are fingerprinted on their first read and later changes raise IOException; a header scan intentionally does not access them. Network resources have no snapshot guarantee and remain disabled by default. Use the native resource policy for opt-in access, path traversal and timeouts. Reopen the index after a reported change.

After disposal, index reads and source-backed XISF block reads raise ObjectDisposedException. Already returned typed buffers and materialized FITS HDUs remain usable. Index attachment reads are serialized; do not dispose the index concurrently with outstanding lazy reads. Full detachment and bounded row/region/plane I/O remain later roadmap steps. Current typed reads allocate a complete selected-image array plus a boolean mask, and compressed XISF requires whole-block decoding.

Evidence: typed precision regressions, index and selective-read regressions. The unsigned offset convention follows the NASA/HEASARC CFITSIO documentation.
