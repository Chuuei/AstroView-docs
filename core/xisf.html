Working with XISF

Open a document and inspect its contents

Use XisfReader.Load(path, options) or LoadAsync for monolithic XISF files and distributed XISH headers. Stream overloads accept an optional base directory for resolving permitted relative blocks. Do not depend on a filename extension to establish the content's type in an application that accepts arbitrary input.

A document can contain multiple images, document properties, creation metadata, document-level tables and application-defined extensions. Each image can also have properties, FITS keywords, tables, a thumbnail, an ICC profile, a CFA pattern, display functions and a working space. Inspect UnavailableObjects and property availability when an ancillary object is retained but cannot be interpreted.

Header parsing and data decoding are separate operations. Selecting an image's typed samples can fail later because a block is missing, its checksum is wrong, its codec is unsupported or a resource budget would be exceeded.

Choose preservation or re-encoding

Goal Approach Consequence
Copy a parsed document with its native content XisfWriter.Write(path, document) Preserves supported XML/opaque content and relocates its blocks as required
Edit metadata while retaining source-aware content document.EditXml(...), then the parsed-document writer Original block references must remain meaningful until writing completes
Change compression, storage placement or editable metadata document.ToEditable(), then editable writer plus options Materializes images; original signatures are not retained
Create an image/document from scratch FromSamples, FromRaw, XisfDocumentData You are responsible for consistent dimensions, channels and metadata

Document preservation does not mean byte-for-byte equality with the original file. Block offsets, header serialization and creation/storage details may differ. Preservation and interoperability are documented separately in the support matrix.

Metadata-only preservation example

Use using System.Xml.Linq; in addition to using AstroView.Core;. This example edits a new document-level property and writes a new file.

public static void PreserveAndEdit(string directory)
{
    var original = XisfReader.Load(Path.Combine(directory, "image.xisf"));
    var edited = original.EditXml(xml =>
    {
        XNamespace ns = xml.Root!.Name.Namespace;
        xml.Root.Add(new XElement(ns + "Property",
            new XAttribute("id", "Example:Note"),
            new XAttribute("type", "String"), "Reviewed"));
    });
    // The parsed-document overload preserves XML and opaque data blocks.
    string output = Path.Combine(directory, "preserved-copy.xisf");
    XisfWriter.Write(output, edited);
    if (!XisfReader.Load(output).Images[0].GetSamples<ushort>()
        .SequenceEqual(original.Images[0].GetSamples<ushort>()))
        throw new InvalidOperationException("Preservation changed samples.");
}

Do not create duplicate property identifiers when applying the same edit to an already edited document. Locate and replace the existing element when that is the intended behavior. Changes to signed XML require a new signature.

Writer settings

Option Default Behavior
Compression None None, Zlib, Lz4, Lz4Hc, Zstd
Shuffle false Rearranges sample bytes before compression; decoding restores sample order
Checksum Sha256 Also supports None, SHA-1, SHA-512 and platform-supported SHA-3 variants
DataBlockStorage Attachment Attachment, Embedded or Inline text-block placement
MaximumInlineBlockSize 65,535 bytes Larger text-encoded blocks fall back to attachment storage
HexEncoding false Text blocks normally use Base64; enables hexadecimal instead
CompressionSubblockSize 0 Zero disables splitting into independent compression subblocks
BlockAlignmentSize 1 Alignment for attached blocks; 1 disables padding
StringsAsDataBlocks false Nonempty String properties may be written as UTF-8 blocks
CreatorApplication Core name/version Application attribution in creation metadata
CreationTime Current UTC time Set explicitly for reproducible creation metadata

These settings apply to writer overloads that serialize editable data or image sequences. The parsed-document overload has no re-encoding options parameter. Inline image samples use embedded Data elements where required by the format.

SHA-3 availability depends on the platform cryptography implementation. Use a widely supported algorithm such as SHA-256 for a portable default and handle an explicit unsupported-algorithm failure rather than silently substituting a digest.

Distributed output

public static void Distributed(string directory)
{
    var editable = XisfReader.Load(Path.Combine(directory, "image.xisf")).ToEditable();
    string header = Path.Combine(directory, "distributed.xish");
    string blocks = Path.Combine(directory, "distributed.xisb");
    XisfWriter.WriteDistributed(header, blocks, editable, new()
    {
        Compression = XisfCompression.Lz4,
        Shuffle = true,
        Checksum = XisfChecksum.Sha256
    });
    if (XisfReader.Load(header).Images[0].GetSamples<ushort>()[3] != ushort.MaxValue)
        throw new InvalidOperationException("Distributed XISF round trip failed.");
    // Keep the header and its referenced block file together.
}

Distribute the header and every file it references together. The example uses relative sibling placement, which the default reader permits. A stream load needs an appropriate base directory to resolve those same paths.

A distributed write publishes two paths and is not an atomic transaction. Applications should use a new output name, manage partial output cleanup and coordinate any final move themselves. Single-file path writers stage their output before replacing a destination; caller-owned streams can contain partial data after errors. See validation and signatures before claiming that a newly written document is fully verified.
