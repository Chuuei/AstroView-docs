Validate a loaded document

public static void ReaderLimits(string directory)
{
    var options = new XisfReaderOptions
    {
        MaximumDataBlockSize = 256 * 1024 * 1024,
        MaximumDecompressionRatio = 1000,
        AllowNetworkResources = false,
        AllowExternalFilePaths = false,
        AllowHeaderRelativeDataBlocks = true,
        AllowHeaderDirectoryTraversal = false
    };
    var document = XisfReader.Load(Path.Combine(directory, "image.xisf"), options);
    var diagnostics = document.Validate();
    foreach (var diagnostic in diagnostics) Console.WriteLine(diagnostic);
    _ = document.Images[0].ReadRawData(); // Forces the primary block to decode and check its digest.
}

Validate() returns diagnostics with severity, code, message and location. Loading and validating a header do not necessarily access all payloads. To check an entire XISF document, decode every primary image and available thumbnail and access any relevant ancillary blocks. Handle an unavailable optional object as a distinct result rather than discarding its preserved XML.

For FITS, tolerant mode retains diagnostics; strict mode rejects error-level findings. Inspect both document diagnostics and ChecksumValid / DataChecksumValid on each HDU. Null means a corresponding checksum was absent, not that verification succeeded. Writers can generate checksums explicitly.

Supply an XSD deliberately

The library accepts a caller-created XmlSchemaSet. Select the XISF schema and revision appropriate to your interchange contract. When loading arbitrary schema files, disable DTD processing and external XML resolution unless your application deliberately supplies a trusted resolver. Schema validation and semantic validation complement each other; neither replaces payload decoding.

Do not download schemas implicitly while opening an image in an offline tool. Ship or configure the trusted schema resources you require. The desktop XSD workflow uses a local caller-selected file and disables network/DTD resolution.

Sign and verify a copy

Use using System.Security.Cryptography; for this recipe.

public static void Signatures(string directory)
{
    var document = XisfReader.Load(Path.Combine(directory, "image.xisf"));
    using RSA key = RSA.Create(3072);
    string signedPath = Path.Combine(directory, "signed.xisf");
    XisfWriter.WriteSigned(signedPath, document, key);
    var signed = XisfReader.Load(signedPath);
    if (!XisfReader.VerifyXmlSignature(signed))
        throw new InvalidOperationException("XML signature verification failed.");
    // Decoding checks declared block digests too; signature verification alone does not decode all pixels.
    _ = signed.Images[0].GetSamples<ushort>();
}

The example owns a temporary RSA key and disposes it when finished. A production application needs its own key storage, identity and trust policy. Verification against a key embedded in the document demonstrates internal integrity; anyone can generate a different key and sign a different document.

Signing requires appropriate digests for attached/external data blocks. Do not strip block checksums before signing. Verification of signed XML is separate from reading all signed image data, so force the blocks to decode when your acceptance policy requires both checks.

Changing signed metadata, image content or relevant serialization requires a fresh signature. Editable re-encoding drops the original signature; preserve the private key separately if you intend to sign new outputs with the same identity. Merely copying the old Signature element is not re-signing.

Handle errors by category

Category Typical exception/result Recommended application behavior
Malformed or inconsistent format FitsFormatException, XisfFormatException Show the operation, file and diagnostic context
Declared digest mismatch XisfChecksumException or FITS invalid checksum result Distinguish corruption from a missing digest
Unsupported capability/type NotSupportedException Explain which operation is unavailable; retain native content if possible
Rejected conversion loss ConversionLossException Present its findings and request an explicit loss decision
Reader policy/budget failure Format, IO or policy exception with explanation Review limits/policy; do not silently retry with unlimited access
Cancellation OperationCanceledException Treat as cancellation and release application-owned partial state

Individual API pages describe their declared exceptions; this table is an integration guide rather than an exhaustive exception list. Logging a failed operation should not expose credential-bearing external resource URLs.
