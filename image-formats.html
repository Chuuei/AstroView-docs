FITS and XISF support

For complete integration guidance and executable examples, use the Core developer guide and API reference guide.

All APIs live in AstroView.Core. The portable XISFLib.Net core was imported from commit 9c0325fcda231603014c497d4d5bbd40477e9030; it is now compiled into AstroView.Core with no XISFLib dependency. Source folders retain their upstream organization (Fits, Xisf, Imaging, Astronomy, Internal). Original type names are retained, including the Xisf prefix.

Reading and writing

using AstroView.Core;

// Typed image creation copies the supplied samples.
var image = XisfImageData.FromSamples(new ushort[] { 0, 100, 200, 65535 }, [2, 2], 1);
image.Properties.Set(XisfKnownProperties.Observation.Object.Name, "M31");
XisfWriter.Write("image.xisf", [image], new XisfWriterOptions
{
    Compression = XisfCompression.Zstd,
    Checksum = XisfChecksum.Sha256
});

var loaded = XisfReader.Load("image.xisf");
ushort[] scientificPixels = loaded.Images[0].GetSamples<ushort>();
var preview = XisfDisplayRenderer.Render(loaded.Images[0], XisfStretchOptions.Auto);
// preview.Pixels contains BGRA32 display pixels; scientific samples are unchanged.

var hdu = FitsHdu.CreateImage(FitsImage.FromPhysicalSamples(
    new ushort[] { 0, 100, 200, 65535 }, [2, 2]), true);
FitsWriter.Write("image.fits", new FitsDocument([hdu]), new FitsWriterOptions
{
    WriteChecksums = true
});
var fits = FitsReader.Load("image.fits");
double[] physicalPixels = fits.Images.First().GetPhysicalSamples();

Dimensions are width, height, then further axes. FromArray uses [height, width] or [height, width, channel]. Parsed typed reads default to planar channel order. FITS scientific axes remain scientific axes unless RGB/RGBA interpretation is explicitly selected. Physical-double reads cannot retain every Int64/UInt64 integer exactly above 2^53; use the exact typed conversion paths when that precision is required.

FitsConverter converts between the two image models. Cross-format conversion can omit metadata or unsupported content: the default loss policy rejects such conversions. Explicitly opt into ConversionLossPolicy.Allow only after reviewing the conversion findings.

Ownership and validation

Caller streams remain open. XISF stream loads buffer their input; path loads lazily reopen the source for data blocks. Keep source files available and unchanged while using lazy data, including metadata blocks. ToEditable() supports edits to parsed content; inspecting a document's XML returns a detached copy.

XISF checksums are checked when blocks are decoded, so loading the header alone does not verify every pixel block. FITS exposes validation diagnostics and optional checksum results. Missing FITS checksums have nullable results. Reader options bound resources and decompression; default XISF options disable network and general external-path access. Embedded signature integrity does not establish signer trust. Single-file path writers stage output before replacement; distributed XISF output and caller-provided streams do not provide the same transactional guarantee.

Dependencies and verification

LZ4 (K4os.Compression.LZ4), Zstandard (ZstdSharp.Port), and Microsoft XML cryptography are runtime NuGet dependencies. No Windows/UI or viewer package is required. Attribution and codec licenses are included in package output.

The imported regression suite covers generated format fixtures, compression, checksums, signatures, metadata, numeric boundaries, malformed input, conversions, and rendering baselines. Additional on-disk tests use hand-constructed FITS/XISF bytes. Upstream external photograph corpus tests and batch-converter application tests are excluded, including the converter-specific assertions in metadata tests. These tests do not establish interoperability with every real-world file variant.
