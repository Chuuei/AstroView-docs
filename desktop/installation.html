AstroView

Installation and launch

Choose the desktop download

Open the repository's GitHub Releases and download AstroView.Desktop-<version>.zip. The separate Core archive is for developers and does not contain the graphical application.

Extract the archive before launching. Choose your platform's directory:

Directory Computer Start
win-x64 64-bit Windows on x64 Double-click AstroView.exe
linux-x64 Linux x64 with a glibc desktop environment Run ./AstroView in a terminal
osx-arm64 macOS on Apple silicon Run ./AstroView in a terminal

Each release executable includes the .NET runtime and native rendering libraries. An installed .NET SDK/runtime is not needed for these executables. Keep the license/notices files with any redistributed copy. The executable can run by itself after extraction; there is no installer or automatic file association.

These release targets do not include Windows ARM, Linux ARM/musl or Intel macOS. The current macOS output is a command-line-launchable executable rather than a notarized .app bundle. Desktop executables are unsigned; follow your operating system's normal trusted-software approval process if it blocks launch.

Linux and macOS permissions

If your ZIP extractor did not retain executable permissions:

chmod +x AstroView
./AstroView

On Linux, use a supported graphical desktop with X11/XWayland, fontconfig and the .NET native prerequisites such as OpenSSL, ICU and zlib. A self-contained download still relies on these operating-system facilities. Launching in a display-less SSH session will not open the graphical workspace.

On first launch, .NET extracts bundled native libraries into its temporary cache. The cache must be writable. An administrator can choose another location using DOTNET_BUNDLE_EXTRACT_BASE_DIR if the normal location is unavailable.

Open files from a terminal

Paths supplied as command-line arguments are opened in the workspace. Quote a path containing spaces:

./AstroView "/path/to/nebula.xisf" "/path/to/another exposure.fits"

On Windows, launch AstroView.exe with the equivalent quoted paths. You can also open files after launch with Open images…, or drag supported files onto the window.

Development builds and CI downloads

If no release has been published, build from source with the .NET 10 SDK:

dotnet restore AstroView.sln --locked-mode
dotnet run --project src/AstroView.Desktop -c Release

To supply files through dotnet run, put them after --. Ordinary CI desktop publish-directory artifacts require .NET 10; run dotnet AstroView.dll inside that downloaded directory. The Release workflow's desktop ZIP is the self-contained download described above.

Installation check

The executable accepts --self-test to check codecs, signatures and native rendering without opening a window. Exit code zero means the installation checks passed. It does not inspect your own photographs. On Linux/macOS:

./AstroView --self-test
echo $?

If launch or the installation check fails, see troubleshooting. Once the window opens, follow first steps.
