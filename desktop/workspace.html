AstroView

Workspace and documents

Window layout

The top bar contains Reference scene and Open images…. The left sidebar has two lists: DOCUMENTS selects a file/session; IMAGES & HDUs selects an item inside that document. The title and summary above the workspaces describe the current selection.

The eight workspaces are Image, Inspect, Analyze, Tables, Coordinates, Integrity, Export and Feature lab. Switching workspace does not save or convert the selected document. Some workspaces expose the whole document, while others operate on the selected image.

The status bar shows the current operation and cancellation availability. Errors appear in a banner near the top; Dismiss hides the message after you have read it. Dismissing an error does not complete the failed operation.

Open files

Use Open images… or Ctrl+O (Command+O on macOS). You can select several files in one picker operation. FITS extensions commonly use .fits, .fit or .fts; XISF uses .xisf; distributed headers use .xish. Drag supported files onto the window or pass paths on the command line as an alternative.

AstroView examines file content when detecting its format. Renaming an unrelated file to .xisf does not make it readable. Raster pictures such as JPEG and PNG are not the astronomical document formats opened by this workspace.

When a batch contains an unreadable file, read the error banner/activity history and check which documents actually opened. Do not assume every selected file succeeded merely because one image appears.

Select an image or extension

  1. Choose the document in DOCUMENTS.
  2. Select the desired entry in IMAGES & HDUs.
  3. Check the dimensions, sample type and channel count above the tabs.
  4. Choose a workspace suitable for that entry.

A FITS primary HDU can be empty; a later extension may hold the image. A table or unknown extension can have useful metadata without an image preview. Use Inspect and Tables rather than treating every blank viewport as a failed file load.

An XISF document can contain several images. Selecting one does not remove the others. Export document… exports the document; use Isolate selected image as a new document first when you want only one image.

Keep distributed files together

A .xish file is a header that can reference a sibling .xisb block file. Open the header, keep the referenced file beside it, and retain both files while working. A document can open its header successfully and fail later when pixels or an ancillary block are accessed if a block file is missing.

Default policy permits header-relative sibling blocks. Network access, general external filesystem paths and traversal outside the header directory are off. Change a policy only if required for a file you intend to access; the reader settings chapter explains how changes apply.

Changes, closing and cancellation

Metadata, XML and table edits are applied in memory. Export a copy before closing a document or exiting if you want to keep those edits. The application does not provide a persistent project/session or automatic saving of the workspace.

Select a document and click Close to remove it and release retained previews and data. Large documents can use considerable memory, particularly after analysis or preview rendering. Closing documents you no longer need is useful even when their source files are compressed.

Long operations temporarily disable conflicting controls. Use Cancel or Escape when cancellation is offered. Some codecs finish their current block before returning. Output publication can temporarily disable cancellation while committing a file. After a canceled open, the app restores the earlier selection where possible; inspect the document list before continuing.
