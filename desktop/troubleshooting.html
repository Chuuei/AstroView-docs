Troubleshooting

Start with the error banner and Feature lab → Activity. Check the selected document/image, the operation you ran and the path it reports before changing settings or trying another export.

Launch problems

Symptom Check and next step
Executable does not start Extract the ZIP first and choose the correct OS/architecture directory
Permission denied on Linux/macOS Restore executable permission with chmod +x AstroView
macOS blocks the download The executable is unsigned/not notarized; use your system's normal trusted-software approval process
Missing .NET runtime A framework-dependent CI publish folder needs .NET 10; use the self-contained Release desktop ZIP if available
Native library/display error Check the platform's graphical/native prerequisites and a writable .NET bundle cache
No window over SSH/headless session Use a graphical desktop to launch the UI; --self-test checks installation without a display

The self-test checks the installation, not the validity of a particular image. See installation for the download types and command-line launch.

A file does not open

Confirm that it is a supported FITS/XISF/XISH document rather than another type with a renamed extension. Check filesystem permissions and whether another program is still writing it. For distributed XISF, locate the referenced XISB file and keep its relative path valid.

If an error mentions a budget, review Feature lab → Reader policy and the file's expected size. A compressed file can expand far beyond its download size. Raising a budget does not bypass a missing codec or every implementation array/memory limit. Reopen the file after changing the reader policy.

Strict FITS validation can reject a file that tolerant mode opens with findings. If your workflow permits tolerant inspection, disable strict-on-open for a new read and examine the findings. Do not equate tolerant opening with full format conformance.

The viewport is blank or dark

Situation What to do
Faint real image in Linear mode Select Auto stretch and click Apply display
Empty FITS primary HDU Select a later image extension in IMAGES & HDUs
Table/unknown extension selected Use Inspect or Tables rather than expecting image pixels
Complex image or general scientific cube Use the stored-sample inspector; a general preview is not implemented
Three-plane FITS known to be RGB Enable Interpret 3rd axis as RGB/RGBA and apply it
Missing/bad data block Run Integrity validation and inspect the decoding error

Do not label a three-axis scientific cube RGB simply to force a picture. That can change the interpretation used by a subsequent conversion.

Measurements look wrong

Check histogram bounds against the scientific sample range. A UInt16 image often needs a much larger range than 0 to 1. Check the chosen channel and include underflow/overflow/non-finite counts when comparing totals.

Statistics use a sample limit, while the histogram counts the complete chosen channel. Normalized statistics and manually chosen histogram bounds are separate. Display stretch is another separate transformation. For very large integers, compare Exact stored samples rather than expecting all Float64 region or statistics values to retain exact text.

If a region read fails, check its X/Y, width/height, channel and 4,096-sample interactive limit. That limit counts all channels, even though only the selected channel is printed.

Edits are missing

Did you click Apply metadata edit, Apply table in memory or Apply XML in memory before exporting? Did you save the whole document or an isolated image? Document-level content remains in the original when an image is isolated. Reopen the actual exported path and inspect the correct scope/image.

Closing a document or exiting before export loses in-memory edits. The workspace does not automatically persist an editing session. A preview PNG cannot retain the scientific document's properties or tables.

For free-text numeric metadata, use decimal points and an explicit TimePoint offset. For JSON, check quotes, commas, row lengths and field types. Applying an existing document-level table identifier replaces that table rather than adding a differently named one.

Export is rejected

Choose a new output name when a path is an active source. For distributed output, choose a new header filename and retain its generated sibling block file.

If conversion findings report omitted content, review the report. Select Allow reported conversion losses only if that output is acceptable. The setting does not enable unsupported pixel types. To preserve a native document instead, choose Keep native document.

If a requested SHA-3 digest is unavailable on your platform, choose a supported digest such as SHA-256. If a signature fails after metadata edits or re-encoding, export the intended final content and sign that copy again.

The operation is slow or uses substantial memory

Analysis/regions can decode a complete block, and typed values plus a preview can coexist in memory. Close unneeded documents, use smaller generated examples for experiments and avoid opening many very large files together. A statistics sample limit does not make the full block decode streaming.

Use Cancel/Escape when offered, allowing for codecs that finish their current block. During output publication, cancellation can be disabled. Do not repeatedly start new operations while the status bar shows the previous one is still busy.

Report a reproducible issue

Record the AstroView version, OS/architecture, file format, operation, selected sample type/dimensions, relevant reader/export settings and exact error/finding code. Prefer a small shareable example or a reference-scene/generator recipe. Remove private observation metadata, paths and credential-bearing resource URLs before sharing logs or files. A screenshot of the error plus the steps that led to it is more useful than an unexplained blank viewport.
