AstroView

Building and maintaining documentation

AstroView has two documentation sets: the Core developer guide and the desktop user manual. Markdown sources remain readable in GitHub. A pinned local DocFX tool builds a searchable HTML edition and generates the complete public Core API reference from the compiled assembly and its XML comments.

Build and preview

Prerequisites: .NET 10 SDK and PowerShell (PowerShell 7 on Linux/macOS). Python 3.10+ is used for snippet/site verification in CI. The HTML/API generator itself does not require Python or Node.js.

From the repository root:

./eng/Build-Documentation.ps1

On Windows PowerShell with local script execution disabled, invoke the script with a process-local execution policy:

powershell -NoProfile -ExecutionPolicy Bypass -File eng/Build-Documentation.ps1

Output is artifacts/documentation/site/index.html. To preview with navigation and search over HTTP:

./eng/Build-Documentation.ps1 -Serve

Open http://localhost:8080 and stop the local server with Ctrl+C. The server is bound to localhost. Serving over HTTP is recommended because browser restrictions on local file: URLs can interfere with search and navigation requests.

CI uploads the complete HTML edition as the documentation-site artifact. Download/extract it and serve that directory, for example with Python:

python -m http.server 8080 --bind 127.0.0.1 --directory path/to/extracted/site

GitHub Pages publication

The documentation is hosted at https://chuuei.github.io/AstroView-docs/. The source repository is private, and the account's current plan does not allow Pages on that repository. The public Chuuei/AstroView-docs repository contains only the generated site and its Pages deployment workflow.

After a successful main-branch push CI run, refresh the hosted documentation:

./eng/Publish-Documentation.ps1 -RunId 123456789

Replace the number with the successful CI run ID. The command downloads its validated documentation-site artifact, checks its contents/links, and pushes only the generated site to the documentation repository. That repository's workflow deploys the update through GitHub Pages. Git and Python 3.10+ are needed; Git Credential Manager supplies the maintainer's existing GitHub credentials. No account credential is stored in the public repository or an Actions secret.

The publisher rejects failed/non-main/non-push CI runs, expired artifacts, application/package binaries and scientific image files. build-info.json identifies the source commit and CI run. Local Git staging uses a fresh checkout under artifacts/pages-publication/; unrelated source changes are not published.

Verify the deployed pages and exact source commit:

python eng/documentation.py published --url https://chuuei.github.io/AstroView-docs/ --commit SOURCE_COMMIT_SHA

The workflow template and documentation repository README are maintained in eng/pages/. Update them through the publisher rather than adding a private source-repository credential to a public deployment workflow.

Structure

Location Purpose
docs/core/ Developer concepts, workflows, recipes and API map
docs/desktop/ Installation, workspace procedures and troubleshooting
docs/core/api/ Generated API YAML; ignored by Git and regenerated on build
docs/images/ Branding and screenshots of the synthetic reference scene
docs/template/ Small additions to DocFX's modern responsive/light/dark template
docs/docfx.json, docs/**/toc.yml Content mappings and navigation
dotnet-tools.json Pinned DocFX version and runtime roll-forward policy
examples/AstroView.Core.Examples/ Compiled/runnable developer examples
eng/documentation.py Snippet synchronization and built-site link checks

The API input is AstroView.Core.dll and its side-by-side XML file in artifacts/documentation/core. Generating from the assembly avoids loading the desktop application into the API extractor and uses the actual built public API. DocFX documents supported public/protected visibility according to its default filter and includes explicit interface implementations.

Keep examples correct

Core guide code fences marked <!-- snippet: region-name --> are synchronized from named C# regions in the example program. Edit the C# first, then run:

python eng/documentation.py sync
python eng/documentation.py check
dotnet run --project examples/AstroView.Core.Examples -c Release -- artifacts/documentation/examples

The check command fails when displayed snippets drift from the compiled example. Examples create only their own small files and assert meaningful sample, checksum, signature, conversion or coordinate results. CI compiles the example project with the solution and runs it on Windows, Linux and macOS.

Update a public API

Update XML documentation in the Core source with the API change. Include units, coordinate conventions, ownership/lifetimes, defaults, precision constraints, parameters, return values and useful exceptions. Keep implementation internals out of the public contract. Do not edit generated API YAML/HTML.

Update the relevant conceptual chapter and the support matrix when behavior changes. An API catalog entry does not by itself expand evaluated format support. Add or adapt a runnable recipe when it provides useful integration coverage.

Update a desktop workflow

Use the exact visible control labels, say which document/image the action uses, describe the expected result, and explain how to save the change. Keep developer implementation details in docs/desktop.md and the Core guide.

Screenshots come from WorkspaceTests.DemoExercisesRealControlsAndEveryWorkspaceRenders. Run that test and copy workspace-0.png through workspace-7.png into the corresponding docs/images/desktop-*.png files when the UI changes. Inspect every image before committing it. Use only the synthetic reference scene: local user photographs and their test captures must remain excluded from published docs.

Verification

Documentation generation treats warnings as errors. After a build, run:

python eng/documentation.py site --directory artifacts/documentation/site

This validates generated local links, fragments, image resources, search data, manual entry points and API pages. It does not crawl external websites. The documentation CI job runs the same checks, while solution CI runs the executable examples on all supported platforms. Review the rendered desktop/mobile pages, search and representative API overload pages when changing navigation or styling.
